# 原 Excel 模板

新上传默认使用原件模式。`grid_config.nativeExcel.version = 1` 标记该模式，包含原文件 base64、SHA-256、文件名和第一张工作表名称。变量地址存入现有 `binding_config`。无需修改数据库结构或迁移旧记录；没有该标记的模板仍使用原网格编辑器和 PDF 渲染器。复制模板会创建新的草稿。发布新版本不会替换已有模板或改变历史账单的模板关联。

上传 → 自动识别已有令牌或手工填单元格地址 → 下载原件/示例 Excel、试打 PDF → 保存绑定 → 发布。合并单元格使用左上角地址，数量和单价列可不绑定。变量只在第一张工作表中填写；工作簿其余部分原样保留。原件模式不提供网页样式编辑，请在 Excel 中修改版式后上传新版本。

生成账单时复制原文件，只替换对应工作表的绑定单元格值。样式、合并区域、图片、其他工作表、公式和打印配置不经网格重建。金额使用数值以支持原有公式，请在 Excel 中设置货币格式。明细只使用指定预留行；超容量拒绝生成并提示上传更多预留行的新版本，不自动改行高或移动页脚。所有绑定位置的原始文字会被替换（令牌支持保留前后标签）。

## PDF 运行要求

服务器需安装 LibreOffice，并配置 `LIBREOFFICE_PATH` 为 `soffice` 的绝对路径；若已在 PATH 可不配置。使用 Node.js 服务进程，允许创建临时目录、启动子进程。Linux 示例：`LIBREOFFICE_PATH=/usr/bin/soffice`。字体必须与模板一致；LibreOffice 与 Microsoft Excel 的字体及排版可能存在差异，正式启用前应核对 PDF，不能保证跨引擎逐像素一致。

每次转换使用独立临时目录和用户配置，执行超时 60 秒，每个服务进程最多同时转换两份。失败明确返回错误，不回退到网格 PDF。原件/示例 Excel 下载不依赖 LibreOffice。账单详情也可下载填好数据的 Excel；接口为原 PDF 路由加 `?format=xlsx`，旧模板不支持此格式但原 PDF 不受影响。

## 验证与上线

运行 `pnpm run test:native-excel`、`pnpm run type-check` 和 `pnpm test`。新测试比较替换前后 OOXML 压缩包中未修改部分的解压字节，并验证图片、边框、公式、打印配置、原件哈希、日期格式（含 1904 日期系统）、富文本分段字体、单行示例及超容量拒绝。

`LIBREOFFICE_PATH=/path/to/soffice node --import tsx scripts/verify-native-excel.ts source.xlsx [bindings.json]` 可执行独立文件验证：只读源文件，将源文件 PDF、填值后的 Excel/PDF 输出到新临时目录，检查只有目标工作表内部文件发生变化。不访问数据库。没有令牌的模板需要传入绑定 JSON。

本改造不执行数据库迁移、种子或批量更新。发布应用代码前安装转换引擎和所需字体；上传 AA/YG 为新的草稿并核对预览。原有只保存网格的模板无法恢复已丢弃的 Excel 原件，需重新上传，不能将旧记录自动切为原件模式。代码回滚前应保留本版本对新模式的读取支持，避免旧程序将新模式误当网格渲染；不要使用不认识原件模式的旧版本服务处理新模板。
